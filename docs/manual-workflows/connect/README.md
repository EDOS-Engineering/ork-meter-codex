# Connect

Use the bundled CLI `python -I -B <plugin-root>/scripts/ork_codex.py meter <action>`. Check `doctor` first. The helper is installed on PATH, selected by absolute `ORK_METER_BINARY`, or built for development with `scripts/build_meter.py --platform-source ../ork-meter` using Go matching that checkout.

For an interactive session with two setup actions, ask the user to run `python -I -B <plugin-root>/scripts/ork_codex.py setup` in their own terminal, then approve the opened browser pairing after checking the fingerprint and enter its claim code at the terminal prompt. Do not run this wizard through an agent tool: it requires a real terminal, owns an interactive Codex CLI session and never receives the claim code through chat. It installs a private component-only package when needed, runs capture, backs up and temporarily configures telemetry, opens Codex with existing model/permission settings, and restores telemetry after that session exits. Subsequent runs reuse the public reference. Existing foreign telemetry or a different marketplace source is not replaced. This does not restart an existing desktop session. Use the manual flow below for persistent desktop capture.

Run `meter prepare` (add `--dev` only for the development platform). Show the returned public pairing reference and approval link. The account holder compares the browser fingerprint, approves the requested connection, then runs `meter claim --reference REF` in their terminal and types the browser's claim code. Never ask them to put the claim code or a credential into chat. Pairing is reusable; use `meter verify --reference REF` for an existing connection.

Start `meter capture --reference REF` in a user-controlled terminal and keep that process running. The helper prints a private telemetry fragment path. On supported Unix hosts, `meter prepare-config --settings PATH --config CURRENT_CONFIG --output NEW_CANDIDATE` creates a review copy without installing it. On Windows that helper operation is unavailable; review and merge the fragment locally. Preserve inference, authentication and managed policy. Never print the fragment content in chat. Restart Codex after applying reviewed telemetry configuration. Restarting capture rotates the port/header and requires a fresh fragment.

Use `meter check-local --settings PATH` for receiver connectivity and `meter diagnose --reference REF --settings PATH` for authorization, receiver and export evidence. `meter status --reference REF` or the `report` status tool checks the hosted receipt. Authorization alone does not prove usage delivery. No receipt means unverified capture, not zero lifetime usage.

Native snapshots overlap and cache/reasoning counters can be subsets. Do not sum them as billed events or infer a dollar saving. The helper filters raw telemetry before upload; local artifacts and source content are never uploaded by this plugin.
